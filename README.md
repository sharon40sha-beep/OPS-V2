# OPS-V2

PWA לניהול תנועת נכסים מאובטחת עם מנוע הגרלה אוטומטי נגד מדפסיות.
React + Vite + TypeScript, Supabase (Postgres) כ-backend.

## הקמה

1. **DB** — הרץ את `supabase/migrations/0001_init.sql` פעם אחת ב-Supabase SQL Editor (פרויקט חדש).
2. **Env** — `cp .env.example .env`
3. `npm install && npm run dev`

Build לפרודקשן: `npm run build` → תיקיית `dist/` (סטטית, כל hosting).

## אבטחה

- הדפדפן משתמש רק ב-publishable key. RLS מופעל על כל הטבלאות **ללא policies**, ול-anon אין הרשאות טבלה —
  כל גישה עוברת דרך RPCs מסוג `SECURITY DEFINER` שמאמתים session token.
- קודים מוצפנים ב-bcrypt (pgcrypto). tokens נשמרים בשרת כ-SHA-256 בלבד.
- 3 ניסיונות כושלים (התחברות או step-up) → נעילה ל-30 דקות + ניתוק כל הסשנים.
- Step-up PIN נדרש ל: בניית שבוע, מחיקת נסיעה, שחרור נעילה.
- סשן: idle של שעתיים בשרת; בצד הלקוח נמחק כשהאפליקציה ברקע ≥ 3 שניות
  (debounce נגד אירועי `visibilitychange` שגויים ב-Safari mobile).
- עובד רואה רק את הנסיעות שלו, פרטים מלאים רק להיום, ולעולם לא את `trip_type`.

## מנוע ההגרלה (`admin_generate_week`)

לכל יום ב'–ו' ולכל נכס פעיל (ימים שכבר יש בהם נסיעה — מדולגים):

1. רכב: מוגרל מתוך סוגים שלא מיצו מכסה חודשית.
2. פרמטרים: נקודת יציאה, ציר, כניסה/יציאה למפעל, ציר חזרה, חלון יציאה (בוקר/צהריים).
3. אנטי-מדפסיות מול 10 הנסיעות האחרונות של הנכס: אין שילוב זהה של רכב+יציאה+ציר+כניסה,
   ואין רכב שמופיע ביותר מ-60% מאותו יום בשבוע (מ-4 דגימות). עד 10 ניסיונות, אחרת הכי פחות חוזר.
4. פיתוי (50%, רק אם הרכב אינו company, מקסימום 3 ב-10 האחרונות): רכב חברה + נהג ראשי,
   יציאה/ציר/כניסה שונים, חלון זמן הפוך, מקושר דו-כיוונית לנסיעה האמיתית.
5. `vehicle_budget.current_month_count` מסונכרן מטבלת הנסיעות (מקור אמת).
