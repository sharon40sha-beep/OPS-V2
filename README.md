# OPS-V2

PWA לניהול תנועת נכסים מאובטחת עם מנוע הגרלה אוטומטי נגד מדפסיות.
React + Vite + TypeScript, Supabase (Postgres) כ-backend.

## הקמה

1. **DB** — הרץ ב-Supabase SQL Editor, לפי הסדר, את כל הקבצים ב-`supabase/migrations/` (0001 → … → 0007).

2. **Env** — `cp .env.example .env`
3. `npm install && npm run dev`

Build לפרודקשן: `npm run build` → תיקיית `dist/` (סטטית, כל hosting).

ב-Vercel (או כל hosting) מגדירים את `VITE_SUPABASE_URL` ו-`VITE_SUPABASE_PUBLISHABLE_KEY` כ-Environment Variables.

### מוסכמה ל-migration חדש
כל migration מתחיל, בתוך ה-transaction, ב:
```sql
select app_private.reset_data_if_pre_pilot();
```
עד שהמנהל לוחץ "הכרז תחילת פיילוט" (הגדרות) — זה מוחק נסיעות והיעדרויות. אחרי ההכרזה
(`app_settings.pilot_start_date`, נעול לשינוי) — לא נוגע בנתונים.

## אבטחה

- הדפדפן משתמש רק ב-publishable key. RLS מופעל על כל הטבלאות **ללא policies**, ול-anon אין הרשאות טבלה —
  כל גישה עוברת דרך RPCs מסוג `SECURITY DEFINER` שמאמתים session token.
- קודים מוצפנים ב-bcrypt (pgcrypto). tokens נשמרים בשרת כ-SHA-256 בלבד.
- 3 ניסיונות כושלים (התחברות או step-up) → נעילה ל-30 דקות + ניתוק כל הסשנים.
- Step-up PIN נדרש ל: בניית שבוע, מחיקת נסיעה, שחרור נעילה.
- סשן: idle של שעתיים בשרת; בצד הלקוח נמחק כשהאפליקציה ברקע ≥ 3 שניות
  (debounce נגד אירועי `visibilitychange` שגויים ב-Safari mobile).
- עובד רואה רק את הנסיעות שלו, פרטים מלאים רק להיום, ולעולם לא את `trip_type`.

- מדיניות קוד (נאכפת בשרת): לפחות 6 תווים, אות גדולה באנגלית, ספרה וסימן.

## מנוע ההגרלה (`admin_generate_week`)

לכל יום ב'–ו' ולכל נכס פעיל (ימים שכבר יש בהם נסיעה — מדולגים). לפני ההגרלה המנהל מסמן מגבלות
לשבוע (עובדים / רכבים לא זמינים לפי יום) — הן נלקחות בחשבון.

- **שני קטעים ביום, בשעות קבועות:** יציאה (בוקר: מחסן → מפעל) וחזרה (צהריים: מפעל → מחסן).
  רכב וצירים מוגרלים לכל קטע בנפרד.
- **אחראי מוצר אחד ליום** (`custodian_id`) — משובץ בשני הקטעים. שאר הצוות יכול להשתנות.
  נבחר מבין הפנויים, עם העדפה קלה למי שהיה אחראי פחות ימים (איזון בלי סבב צפוי).
  אין עובד פנוי → אין קטעים לנכס באותו יום, והמנהל מקבל "אין עובד פנוי ל-A1 ב-[תאריך] - נדרשת התערבות ידנית".
- **הנהג הראשי חלק מכל קטע:** ברכב חברה הוא נוהג עם האחראי (אף פעם לא לבד עם המוצר); ברכב אחר
  הוא יוצא באותה שעה לבד ברכב החברה כפיתוי (ציר וכניסה/יציאה שונים). מכסה: עד 5 פיתויים ב-10 הקטעים
  האחרונים מאותו כיוון.
- **יציאה מהמחסן תמיד מהחניה המקורה**; אפשרויות "רק רכב חברה" (יציאה מהמפעל דרך הכניסה הראשית)
  מוגרלות רק לרכב חברה.
- **קטע עם פיתוי — רק אפשרויות "מותר בפיתוי"**, לשני הרכבים: יציאה מהמחסן מהחניה המקורה; כניסה
  למפעל דרך החניון התת-קרקעי (מהראשי/מהרחוב האחורי) או הסימטה; יציאה מהמפעל מתוך החניון
  (לראשי או לרחוב האחורי — פיצול בין הרכבים תקין). נאכף גם ב-trigger במסד.
- **אנטי-מדפסיות** — 10 מועמדים לכל קטע, נבחר בעל הציון הנמוך:
  - קצר טווח (חובה): אין שילוב זהה ב-10 הקטעים האחרונים; אין רכב מעל 60% באותו יום בשבוע.
  - ארוך טווח (כל ההיסטוריה מתחילת הפיילוט): העדפת ערכים שהיו בשימוש פחות מחלקם ההוגן — רכב
    כללי, רכב לפי יום בשבוע, רכב החזרה בהינתן רכב הבוקר, צירים/כניסות/יציאות.
- **דוח "ניתוח דפוסים"** (לוח בקרה): כמה טוב יריב היה מנחש את הרכב — עיוור, לפי יום בשבוע, ולפי
  רכב הבוקר — לתקופה של 30/90/365 יום או הכול.
- `vehicle_budget.current_month_count` מסונכרן מטבלת הנסיעות (כל קטע = שימוש ברכב).
