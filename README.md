# OPS-V2

PWA לניהול תנועת נכסים מאובטחת עם מנוע הגרלה אוטומטי נגד מדפסיות.
React + Vite + TypeScript, Supabase (Postgres) כ-backend.

## הקמה

1. **DB** — הרץ ב-Supabase SQL Editor, לפי הסדר, את כל הקבצים ב-`supabase/migrations/` (0001 → … → 0015).

2. **Env** — `cp .env.example .env`
3. `npm install && npm run dev`

Build לפרודקשן: `npm run build` → תיקיית `dist/` (סטטית, כל hosting).

ב-Vercel (או כל hosting) מגדירים את `VITE_SUPABASE_URL` ו-`VITE_SUPABASE_PUBLISHABLE_KEY` כ-Environment Variables.

### מוסכמה ל-migration חדש
כל migration מתחיל, בתוך ה-transaction, ב:
```sql
select app_private.reset_data_if_pre_pilot();
```
עד שהמנהל לוחץ "הכרז תחילת פיילוט" (הגדרות) — זה מוחק נסיעות והיעדרויות. אחרי ההכרזה
(`app_settings.pilot_start_date`, נעול לשינוי) — לא נוגע בנתונים.

## אבטחה

- הדפדפן משתמש רק ב-publishable key. RLS מופעל על כל הטבלאות **ללא policies**, ול-anon אין הרשאות טבלה —
  כל גישה עוברת דרך RPCs מסוג `SECURITY DEFINER` שמאמתים session token.
- קודים מוצפנים ב-bcrypt (pgcrypto). tokens נשמרים בשרת כ-SHA-256 בלבד.
- 3 ניסיונות כושלים (התחברות או step-up) → נעילה ל-30 דקות + ניתוק כל הסשנים.
- Step-up PIN נדרש ל: בניית שבוע, מחיקת נסיעה, שחרור נעילה.
- סשן: idle של שעתיים בשרת; בצד הלקוח נמחק כשהאפליקציה ברקע ≥ 3 שניות
  (debounce נגד אירועי `visibilitychange` שגויים ב-Safari mobile).
- **נראות:** לפי החלטת הבעלים כל העובדים רואים את כל המשימות של הצוות (השבוע והבא) עם כל הפרטים, כולל
  מסלולים ופיתויים — לצפייה בלבד (`team_week`). כפתורי סטטוס — רק בקטע של העובד עצמו, ביום המשימה
  (`worker_set_status`); שינוי משימה — רק ב-RPC של מנהל.

- **פתיחה/סגירת משימה:** העובד בקטע לוחץ "יצאתי"/"חזרתי" — נרשמות שעות יציאה וחזרה. קטע פיתוי (הנהג הראשי
  בלי גישה למערכת) נפתח ונסגר **אוטומטית יחד עם הקטע האמיתי** (trigger `trips_mirror_decoy`).
  המנהל יכול לפתוח/לסגור כל משימה ולתקן שעות (`admin_set_status`, מסומן "עודכן ע״י מנהל").
- **משימה מעל שעה וחצי** נסגרת רק עם סיבה: שכחתי לסגור / עיכוב בדרך / המתנה במפעל / אחר (+טקסט, חובה ב"אחר").
  "שכחתי לסגור" מחייב שעת חזרה בפועל, והיא נשמרת במקום שעת הלחיצה. נאכף בשרת (`app_private.close_check`).

- **אזור זמן:** כל השעות והתאריכים לפי **שעון החוף המזרחי בארה"ב** (`America/New_York`, כולל שעון קיץ) —
  בשרת (`app_private.today()`) ובתצוגה (`TZ` ב-`src/lib/dates.ts`), בלי קשר להגדרת המכשיר.

- מדיניות קוד (נאכפת בשרת): לפחות 6 תווים, אות גדולה באנגלית, ספרה וסימן.

## מנוע ההגרלה (`admin_generate_week`)

לכל יום ב'–ו' ולכל נכס פעיל (ימים שכבר יש בהם נסיעה — מדולגים). לפני ההגרלה המנהל מסמן מגבלות
לשבוע (עובדים / רכבים לא זמינים לפי יום) — הן נלקחות בחשבון.

- **שני קטעים ביום, בשעות קבועות:** יציאה (בוקר: מחסן → מפעל) וחזרה (צהריים: מפעל → מחסן).
  רכב וצירים מוגרלים לכל קטע בנפרד.
- **אחראי מוצר אחד ליום** (`custodian_id`) — משובץ בשני הקטעים. שאר הצוות יכול להשתנות.
  נבחר מבין הפנויים, עם העדפה קלה למי שהיה אחראי פחות ימים (איזון בלי סבב צפוי).
  אין עובד פנוי → אין קטעים לנכס באותו יום, והמנהל מקבל "אין עובד פנוי ל-A1 ב-[תאריך] - נדרשת התערבות ידנית".
- **הנהג הראשי חלק מכל קטע:** ברכב חברה הוא נוהג עם האחראי (אף פעם לא לבד עם המוצר); ברכב אחר
  הוא יוצא באותה שעה לבד ברכב החברה כפיתוי (ציר וכניסה/יציאה שונים). מכסה: עד 5 פיתויים ב-10 הקטעים
  האחרונים מאותו כיוון.
- **יציאה מהמחסן תמיד מהחניה המקורה**; אפשרויות "רק רכב חברה" (יציאה מהמפעל דרך הכניסה הראשית)
  מוגרלות רק לרכב חברה.
- **קטע עם פיתוי — רק אפשרויות "מותר בפיתוי"**, לשני הרכבים: יציאה מהמחסן מהחניה המקורה; כניסה
  למפעל דרך החניון התת-קרקעי (מהראשי/מהרחוב האחורי) או הסימטה; יציאה מהמפעל מתוך החניון
  (לראשי או לרחוב האחורי — פיצול בין הרכבים תקין). נאכף גם ב-trigger במסד.
- **אנטי-מדפסיות** — 10 מועמדים לכל קטע, נבחר בעל הציון הנמוך:
  - קצר טווח (חובה): אין שילוב זהה ב-10 הקטעים האחרונים; אין רכב מעל 60% באותו יום בשבוע.
  - ארוך טווח (כל ההיסטוריה מתחילת הפיילוט): העדפת ערכים שהיו בשימוש פחות מחלקם ההוגן — רכב
    כללי, רכב לפי יום בשבוע, רכב החזרה בהינתן רכב הבוקר, צירים/כניסות/יציאות.
- **דוח "ניתוח דפוסים"** (לוח בקרה): כמה טוב יריב היה מנחש את הרכב — עיוור, לפי יום בשבוע, ולפי
  רכב הבוקר — לתקופה של 30/90/365 יום או הכול.
- `vehicle_budget.current_month_count` מסונכרן מטבלת הנסיעות (כל קטע = שימוש ברכב).

## משימות מיוחדות (`admin_save_manual_trip`)

- המנהל מוסיף בלוח הבקרה, לכל יום ב'–ו', משימה ידנית: נכס, מ- ← ל- (מחסן / מפעל / מתקן חוץ — מתקן חדש נשמר
  לרשימה), בוקר / צהריים / אחה"צ-ערב + שעה מדויקת (רשות), רכב, צוות, אחראי (רשות), מסלול והנחיות בטקסט חופשי.
- העובדים מקבלים אותה כמו כל משימה (יצאתי/חזרתי, שעות, סיבה מעל שעה וחצי).
- "בנה שבוע" ו"רענן שבוע" לא נוגעים בה. המנוע **סופר** אותה: רכב (מכסות, איזון לפי יום, שילובים אחרונים), ויציאה
  מהמחסן / כניסה ויציאה מהמפעל כשהיא משתמשת בהן (נבחרות מהרשימות). הצד של מתקן החוץ נשמר להיסטוריה בלבד.
- אין פיתוי אוטומטי ואין אכיפת נהג ראשי — מוצגות אזהרות (נהג ראשי לא משובץ, רכב/עובד תפוס באותו זמן, מכסה).
- **פיתוי ידני** (`admin_save_decoy`): אחרי יצירת משימה מיוחדת — "לשייך משימת פיתוי?"; וגם "+ הוסף פיתוי" בכל משימה
  מתוכננת (מיוחדת או רגילה) שאין לה פיתוי. הפיתוי יוצא באותו זמן ונפתח/נסגר אוטומטית עם המשימה. רק נקודות "מותר
  בפיתוי" — גם בפיתוי וגם במשימה עצמה (נאכף ב-trigger). מכסת 5/10 מוצגת כאזהרה. פיתויים לא בניתוח הדפוסים.

## רענון שבוע (`admin_refresh_week`)

- step-up + מסך אישור (`admin_refresh_preview`) שמראה בדיוק אילו ימים/נכסים יוגרלו מחדש.
- ברירת מחדל: מחר עד שישי. "כולל היום" — רק מה שעוד לא התחיל. "השבוע הבא" — יוצר/מרענן גם אותו.
- משימה שהתחילה/בוצעה לא משתנה. הלוך של היום התחיל → בחזרה נשארים הרכב והצוות; מוגרלים רק ציר החזרה
  והיציאה מהמפעל.
- כל הכללים של המנוע חלים; מכסות לפי מה שבוצע + מה שמתוכנן; יום שמוגרל מחדש שונה מהתוכנית שבוטלה ב-4
  משתנים לפחות מתוך 7; פיתוי מוגרל מחדש.
- טרנזקציה אחת: יום בלי תוכנית חוקית → הכול מתבטל, עם היום והכלל שחסם.

### היסטוריה
- הטבלה `trips_all` מחזיקה הכול; `trips` היא view בלי משימות `cancelled_refresh`, ולכן ניתוח הדפוסים,
  הקורלציות, המכסות ומסכי העובדים מתעלמים מתוכנית שבוטלה. משימה שבוטלה מקושרת למחליפה (`replaced_by`)
  ואי אפשר למחוק/לשנות אותה. **מחיקה** של משימה מתוכננת מסמנת אותה `deleted` (נעלמת מהמסכים ומהחישובים, נשמרת בהיסטוריה, לא ניתנת לשינוי). `refresh_log` — append-only (גם לא מנהל). TRUNCATE חסום.
- **migration שמוסיף עמודה לנסיעות:** `alter table public.trips_all ...` ואז `create or replace view public.trips`.
